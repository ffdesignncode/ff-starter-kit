# Мади: обновление сборки стартового пакета

Схема ниже известна по скриншоту сборки; исходники бота здесь отсутствуют.
Имена Go-переменных и текущие правила Makefile нужно проверить в репозитории бота.
Этот файл описывает необходимые изменения, но не означает выполненный деплой.

## 1. Пути в packKit

Комплект лежит в корне этого репозитория, без вложенной `starter-kit/`.
В `packKit` сохрани обновление `.cache/ff-starter-kit`, затем замени источники
копирования по таблице. Назначения относятся **к репозиторию бота**:

| Источник относительно корня комплекта | Назначение в репозитории бота |
|---|---|
| `environment/macos/SETUP.md` | `cmd/botFFsetup/kit/SETUP.md` |
| `environment/windows/SETUP.md` | `cmd/botFFsetup/kit/SETUP_WINDOWS.md` |
| `codex/SUBSCRIPTION.md` | `cmd/botFFsetup/kit/SUBSCRIPTION.md` |
| `README.md` | `cmd/botFFsetup/kit/README.md` — добавить |
| `codex/SETUP.md` | `cmd/botFFsetup/kit/CODEX_SETUP.md` — добавить |

Три прежних имени назначения можно сохранить; возвращать такие дубли в корень
самого комплекта не нужно. README объясняет начало, CODEX_SETUP задаёт общий
порядок, остальные документы содержат команды ОС и справку аккаунта.

## 2. Контекст ответов бота и порядок сборки

В загрузчике контекста добавь **все пять** документов, а не только прежние три.
Если они подключены через `//go:embed`, подготовь их **до `go build`**:
содержимое встраивается при компиляции ([документация Go](https://pkg.go.dev/embed)).
Проверь порядок `packKit` и сборки в `make copyBotFFsetup`.
Отсутствующий исходный документ или ошибка упаковки должны остановить сборку;
при ошибке рабочие артефакты не заменяются.

## 3. ZIP и выкладка

После обновления кеша зафиксируй один commit комплекта для ZIP и пяти документов.
Создавай ZIP заново во временном файле, проверь его и затем замени
`cmd/botFFsetup/kit/ff-starter-kit.zip`. Не дописывай старый архив: в нём могут
остаться удалённые файлы.

В студенческий ZIP включай только `.gitignore`, `README.md`, `codex/` и
`environment/` — сейчас это 13 файлов. Удобный общий префикс — `ff-starter-kit/`.
Не включай `.git`, кеши, временные файлы и эту инструкцию для сборки.

Выложи новый бинарник и проверенный ZIP вместе из одной сборки. Существующий
путь выдачи архива можно сохранить, если он совпадает с текущим кодом бота.
Для отката сохрани предыдущую пару «бинарник + ZIP». Проверка репозитория ботом
во время работы для этой миграции не требуется.

## 4. Проверка после выкладки

Скачай ZIP через кнопку «Стартовый пакет»: внутри должны быть README, `codex/`
и `environment/`, а стартовое сообщение должно вести в `codex/SETUP.md`.
Спроси бота, как начать настройку: ответ должен исходить из уже установленного
Codex, открытия локальной папки и одного сообщения из README.
