# Настройка под себя — инструкция для Claude Code

> Студент открыл локальную папку комплекта в Claude Code (терминал или вкладка
> Code в приложении Claude) и поручил настройку под себя. Выполняй её
> самостоятельно, коротко сообщай результат каждого этапа (1–2 строки).
> До знакомства объясняй просто; затем учитывай выбранные язык, уровень и формат.
>
> Эта настройка **не устанавливает программы**: только знакомство, правила
> и файловая память рабочего проекта. Программы, голос, GitHub и Figma
> настраиваются отдельно (для Codex — `codex/SETUP.md`), здесь их не ставь.
>
> Не выдумывай. Проверяй результат реальными действиями; не объявляй
> непроверенное готовым. Пароли, токены, коды и личный вход выполняет человек
> вне чата. Оплаты, создание аккаунтов и публикации в поручение не входят.

## 1. Проверить среду

Проверь ОС, фактическую папку комплекта и доступ к её файлам: должны быть видны
`README.md` и папка `claude/`. Если работаешь не на компьютере студента
(облако, удалённый host) — сообщи это и объясни, как открыть локальную папку.
Существующие глобальные настройки Claude Code (`~/.claude/`) не меняй.

## 2. Познакомиться и выбрать стиль

Проведи [короткую анкету](QUESTIONNAIRE.md), учитывая уже известные ответы.
Сразу применяй согласованные язык, глубину объяснений, формат и примеры.
Пропуски и отказ не блокируют настройку. Личные ответы пока не записывай:
сохранение по желанию — только после выбора рабочего проекта и проверки защиты ниже.

## 3. Правила и память проекта

⚠️ Согласуй со студентом рабочую папку и её название. Комплект хранит шаблоны;
рабочий проект — выбранная студентом папка. Не создавай `CLAUDE.md` внутри
самого комплекта и не создавай папку проекта вслепую.

Перед переносом прочитай действующие правила: `CLAUDE.md` и `CLAUDE.local.md`
в рабочей папке и родительских папках, а также глобальный `~/.claude/CLAUDE.md`.
Не удаляй и не обходи их молча. Если правило конфликтует с выбранными
предпочтениями, согласуй именно конфликт.

Перенеси в рабочий проект:

| Из `claude/` | В рабочий проект |
|---|---|
| `CLAUDE.template.md` | `CLAUDE.md` в корне |
| `ARCHITECTURE.md` | `ARCHITECTURE.md` в корне |
| `docs/SESSION_STATE.md` | `docs/SESSION_STATE.md` |

`CLAUDE.md` подключает карту и состояние строками `@ARCHITECTURE.md`
и `@docs/SESSION_STATE.md` — сохрани их в начале файла.

Перед записью проверь каждый целевой файл. Отсутствующий создай, существующий
прочитай, сравни и объедини, сохранив правила, факты и историю. До изменения
существующего сделай резервную копию вне репозитория, в папке, доступной только
пользователю. Не копируй поверх файлов вслепую.

Адаптируй `CLAUDE.template.md` по результату анкеты, а не копируй универсальный
профиль новичка: запиши согласованные неперсональные инструкции о языке,
глубине, формате и примерах. Замени относящиеся к ним значения по умолчанию,
не оставляй рядом противоречащие правила. Имя, роль, цели, инструменты,
страну и регион в `CLAUDE.md` не переноси. Если пользователь запретил любое
сохранение ответов, оставь персонализацию только в текущем диалоге,
а общие правила проекта создай без его ответов. При повторной настройке
меняй только согласованные предпочтения, сохраняя остальные правила и факты.

В новой рабочей папке заполни карту реальными данными. В памяти укажи текущий
статус и следующий шаг.

### Личная память по желанию

Используй результат анкеты, не проводи второй опрос. Лишь если пользователь
согласен запомнить личный контекст, запиши согласованный минимум в
`docs/USER.md` рабочего проекта и добавь в `CLAUDE.md` строку `@docs/USER.md`.
При отказе не создавай и не обновляй этот файл. Чужую память не копируй.

**До записи личного:** добавь отдельной строкой `/docs/USER.md` в корневой
`.gitignore` рабочего проекта, сохранив существующие правила. Если Git-репозиторий
уже есть, проверь из корня проекта `git ls-files -- docs/USER.md`. Если файл
отслеживается — останови запись личных данных, объясни, что ignore не убирает
их из истории, и согласуй дальнейшие действия. Для неотслеживаемого файла проверь
`git check-ignore -- docs/USER.md`: путь должен быть исключён. Если Git ещё нет,
правило сохрани, но защиту не объявляй проверенной и личные данные пока
не записывай; не выполняй `git init` только ради анкеты. Личные факты
не дублируй в карте, SESSION_STATE или других файлах, которые могут попасть в Git.

Встроенная автопамять Claude Code (`/memory`) не заменяет эти файлы: правила
и состояние проекта храни в `CLAUDE.md`, карте и SESSION_STATE.

## 4. Проверка

1. Попроси студента открыть рабочую папку в **новой** сессии Claude Code
   и выполнить `/memory`: в списке должен быть `CLAUDE.md` проекта.
2. На обычном вопросе проверь, что Claude отвечает в выбранном стиле
   и знает текущий шаг из `docs/SESSION_STATE.md`.

Покажи короткий итог:

- [ ] ОС и локальная папка подтверждены.
- [ ] Анкета предложена без повторных вопросов; пропуски и отказ учтены.
- [ ] `CLAUDE.md`, `ARCHITECTURE.md`, `docs/SESSION_STATE.md` в рабочем проекте,
      существующие файлы сохранены.
- [ ] Личная память: записана по согласию после проверки защиты
      либо «не требуется».
- [ ] Новая сессия подхватила правила — или отмечено, что ещё не проверено.

Не говори «всё работает», если часть не проверена.

Официально: [память Claude Code и CLAUDE.md](https://code.claude.com/docs/en/memory).
